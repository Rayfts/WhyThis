# Support

WhyThis is a pre-1.0 open-source project. Support is community-driven and best-effort; there is no guaranteed response time or commercial SLA.

## Before opening an issue

Check the README and documents under `docs/`, then run:

```bash
whythis doctor
whythis harnesses
```

For harness-specific questions, include the harness name/version and `whythis capabilities <id>` output when safe to share.

## Bugs

Use the bug-report form. Include the WhyThis commit/version, Git version, Go version, OS, the target command, and a small repository/history that demonstrates the problem when possible. Sanitized command output is useful; private repository content should not be posted accidentally.

## Feature requests

Use the feature-request form and describe the archaeology or maintenance problem first. For new evidence sources, explain how provenance can be preserved and how the feature behaves without an AI harness.

## Security

Do not report vulnerabilities through a normal issue. Follow `SECURITY.md`.

## Questions

Focused usage questions are welcome as GitHub issues when the README/docs do not already answer them. Keep one topic per issue so answers remain searchable.
