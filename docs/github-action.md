# GitHub Actions usage

WhyThis ships `.github/workflows/whythis-pr.yml` as a low-noise PR integration. It runs automatically on opened, synchronized and reopened pull requests to produce a full evidence artifact. It can also be invoked manually with `workflow_dispatch`.

**Comments are opt-in.** Automatic PR runs post no conversation comment unless repository variable `WHYTHIS_AUTO_COMMENT` is set to `true`. Manual dispatch can enable the `comment` input. A comment is posted/updated only when at least one changed file crosses the deterministic historical-risk threshold. The threshold is selected from manual input, repository variable `WHYTHIS_RISK_THRESHOLD`, or defaults to `50`.

The comment includes path, deterministic score, evidence confidence, fix-like commit count, revert count, churn and sensitive-code classification. Sensitive classification is separate from score. Neither the score nor the comment is generated by an LLM or presented as a defect probability. The detailed artifact retains FACT / INFERENCE / UNKNOWN separation.

Manual inputs:

- `pr` — pull-request number.
- `comment` — opt in to posting/updating the low-noise comment.
- `risk_threshold` — minimum deterministic score for posting.

Repository variables for automatic runs:

- `WHYTHIS_AUTO_COMMENT=true` — opt in to PR comments.
- `WHYTHIS_RISK_THRESHOLD=<0-100>` — optional threshold override.

The workflow uses the built-in `GITHUB_TOKEN`. `contents: read` and `pull-requests: read` are used for evidence collection; `issues: write` is needed for the optional PR conversation comment. Fork PR tokens may be read-only; the artifact path still works while comment mutation follows GitHub's token-permission rules. Local Git analysis itself does not require GitHub.
